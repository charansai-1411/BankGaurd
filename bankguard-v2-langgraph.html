Foundation
5 Principles — Agentic Edition
These replaced the original RAG-only principles when LangGraph was introduced. Every tool, every node, every edge is justified against these.
01
Reason Before Acting
Every section is evaluated before any tool is called. The agent decides if a section is relevant before spending tokens on retrieval. Skipping irrelevant sections is not a bug — it is intelligent behavior.
02
Tools Over Prompts
Structured operations — vector search, code analysis, web scraping, evidence validation — are tools with typed inputs and outputs. The LLM reasons; tools act. Never ask the LLM to do what a deterministic function can do better.
03
Delegate, Don't Duplicate
When an RBI regulation section touches APIs, the Compliance Agent calls the API Agent. When it touches code, it calls the Codebase Agent. Each agent owns its domain. No agent duplicates another's knowledge or tools.
04
Explicit State Graph
The agent loop is a LangGraph StateGraph — every node and edge is explicit Python. No hidden orchestration. No magic. You can draw the graph, explain every transition, and debug any failure by inspecting the state at any node.
05
Evidence Is Mandatory
Every gap finding must cite the exact retrieved chunk as evidence. The Evidence Validator tool verifies citations before the report is compiled. The LLM says "I don't know" if similarity falls below 0.70 — never hallucinates regulation text.

Core Intelligence
LangGraph ReAct Loop — Full Diagnosis Mode
This is the state graph every agent runs in Full Diagnosis mode. Each node is a Python function. Each edge is a conditional decision. The agent iterates every regulation section — skipping irrelevant ones, calling tools on gaps, delegating to peer agents when needed.
LangGraph StateGraph — Agent Full Diagnosis Loop
Start Node
Initialize State
Load all regulation chunks for this agent domain (is_active=true, ordered by chunk_index). Set current_chunk_index=0, findings=[], call_depth from job context. Begin iteration.
next chunk
Decision Node
Relevance Reasoner
Agent reads the regulation chunk and reasons: Is this section relevant to compliance gaps? Does it contain a mandate, requirement, or control that a bank must implement?

Routes to: SKIP (not a compliance requirement — e.g. preamble, definitions) · INVESTIGATE (contains a mandate that needs checking) · DELEGATE (domain belongs to a peer agent — API/code related)
Route: Skip
Skip Section
Section is preamble, definition, or non-actionable. Log skip reason to state. Advance chunk_index. Return to Relevance Reasoner.
Route: Investigate
Call Tools
Section contains a compliance mandate. Proceed to Tool Caller node to retrieve bank policy evidence and analyze the gap.
Route: Delegate
Call Peer Agent
Section is API/code/cyber domain. Call the appropriate peer agent via Inter-Agent Call Tool with call_depth+1. Await result. Merge finding into state.
investigate path
Tool Node
Tool Caller
Agent decides which tools to call based on the regulation section content:
• Vector Search Tool — retrieve matching bank policy chunks (top-5, cosine_sim ≥ 0.70)
• Section Expander Tool — if retrieved chunk seems cut off, fetch surrounding context
• RBI Scraper Tool — if agent suspects local corpus is outdated for this section

Tool results returned to agent state. Agent reasons about the results.
Decision Node
Evidence Quality Check
Agent evaluates retrieved bank policy chunks: Are the similarity scores strong enough (≥ 0.70)? Is there enough context to make a gap determination?

Routes to: RETRY (scores weak — rephrase query and call Vector Search again, max 3 retries) · GAP FOUND (bank policy doesn't cover this regulation) · COMPLIANT (bank policy adequately covers this section) · INSUFFICIENT (after 3 retries, still no strong evidence — log as "unable to verify")
gap found path
Tool Node
Gap Analyzer + Evidence Validator
Gemini generates the gap finding with evidence citation. Then Evidence Validator Tool is called to verify the cited regulation chunk actually exists in pgvector. If validation fails → finding is flagged as unverified rather than discarded. Severity Calculator Tool assigns CRITICAL/HIGH/MEDIUM/LOW based on obligation_type and coverage score.
State Update Node
Append Finding to State
Validated GapFinding appended to state.findings. Advance chunk_index. Check if more chunks remain → loop back to Relevance Reasoner. If all chunks processed → proceed to Compile.
all chunks done
End Node
Compile + Generate Report
All findings deduplicated by regulation_clause_ref. Sorted by severity. Report Writer Tool called → Jinja2 + WeasyPrint → PDF → Cloudflare R2 → pre-signed URL. Job status updated to READY. Audit log written to Supabase.

LangGraph State object carries across all nodes: { job_id, agent_domain, mode, call_depth, regulation_chunks[], current_chunk_index, findings[], retry_count, session_memory[], report_url }. Every node reads from and writes to this state. This is what makes the loop resumable — if the worker crashes mid-analysis, LangGraph checkpoints (stored in Redis) let it resume from the last completed node.

Agent Capabilities
Every Tool — Signature, Purpose, Retry Logic
Each tool is a typed Python function decorated with LangGraph's tool interface. The LLM decides which tools to call and in what order. Tools are deterministic — no LLM inside a tool, except the Inter-Agent Call Tool which invokes a full agent.
Retrieval Tool
Vector Search
All Agents
search(query: str, namespace: str, top_k: int = 5) → List[Chunk]
What it does: Embeds the query via text-embedding-004 → cosine similarity search against the specified pgvector namespace → returns top-K chunks with similarity scores. Filters is_active=true always.

Namespaces: "{agent_domain}_regulation" and "{agent_domain}_bank_doc". Always called twice per investigation — once per namespace.

Threshold: Returns chunks only where cosine_sim ≥ 0.70. If no results, returns empty list — agent treats this as "no bank coverage" signal.
Retry logic: If results are weak (all sim scores 0.70–0.75), agent rephrases the query using Gemini and retries. Max 3 retries per section. After 3 failures → logged as "insufficient evidence."
Retrieval Tool
Section Expander
All Agents
expand(chunk_id: str, window: int = 2) → List[Chunk]
What it does: Fetches the N chunks before and after a given chunk by chunk_index. Called when the agent detects a retrieved chunk ends mid-sentence or mid-clause — a sign the relevant content continues in adjacent chunks.

When called: Agent reasons "this chunk seems incomplete" → calls Section Expander → receives surrounding context → re-evaluates with full context.

Why important: RBI circulars have multi-paragraph clauses. A single 800-token chunk may capture a requirement header but not the full obligation text. Without expansion, the agent would judge coverage on incomplete regulation text.
No retry needed — deterministic DB fetch by chunk_index range.
External Tool
RBI Scraper
All Agents
scrape_rbi(query: str, circular_type: str) → List[Document]
What it does: Scrapes RBI's official website (rbi.org.in) for the latest circular matching the query. Returns document title, date, URL, and text content. Used when the agent suspects the local corpus is outdated — e.g. regulation section references a newer amendment.

When called: Agent detects phrases like "as amended", "refer to latest circular", or finds the local corpus has no chunks dated within the last 6 months for this topic → calls scraper → if newer circular found → ingests it on the fly → re-runs Vector Search.
Retry logic: If scraper fails (network/rate limit) → agent continues with existing corpus and flags finding as "may be based on outdated regulation — please verify."
Validation Tool
Evidence Validator
All Agents
validate(chunk_id: str, cited_text: str) → ValidationResult
What it does: After Gemini generates a gap finding with an evidence citation, this tool verifies the cited chunk actually exists in pgvector and that the cited text matches the stored chunk content (fuzzy match, threshold 0.85). Prevents hallucinated regulation citations.

Why critical: This is a compliance product. A falsely cited RBI clause in an audit report is legally dangerous. This tool is a hard gate — no finding passes to the report without validation passing.
On failure: Finding is marked evidence_verified: false and flagged with a warning in the report: "Evidence citation could not be verified — human review required." Never silently dropped.
Scoring Tool
Severity Calculator
All Agents
calculate_severity(obligation_type: str, coverage_score: float, is_mandatory: bool) → Severity
What it does: Deterministic severity scoring — no LLM involved. Takes the regulation's obligation type and the bank policy coverage score (cosine similarity of best match) → returns CRITICAL / HIGH / MEDIUM / LOW.

Logic: CRITICAL = mandatory + no coverage (sim=0). HIGH = mandatory + weak coverage (0 < sim < 0.70). MEDIUM = advisory + no coverage. LOW = advisory + weak coverage.

Why deterministic: LLM severity judgments are inconsistent across runs. Same inputs must produce the same severity every time for an audit report to be defensible.
No retry needed — pure function, no I/O.
Delegation Tool
Inter-Agent Call
Peer-to-Peer
call_agent(agent_type: str, query: str, context: str, call_depth: int) → AgentResult
What it does: Calls a peer agent with a specific query and the regulation section context. The called agent decides — based on query complexity — whether to run its full LangGraph pipeline or return a quick focused answer.

Call depth enforcement: If call_depth ≥ 2, this tool refuses to call and returns: "Max call depth reached — analysis limited to current agent scope." Prevents infinite loops.

Agent decision (full vs quick): If query is broad ("analyze all API security implications") → full pipeline. If query is narrow ("does /payments endpoint use OAuth2?") → quick focused retrieval + LLM answer without full diagnosis loop.
On peer agent failure: Returns partial result with error flag. Calling agent logs the delegation failure and continues with its own analysis, noting the limitation in the report.
Peer-to-Peer Architecture
How Agents Communicate
Agents call each other as tools — no master orchestrator. Each agent decides when to delegate based on the regulation section's domain. Call depth is tracked in LangGraph state to prevent circular loops.
Agent Communication Map — V1
RBI Compliance Agent
Primary agent for policy compliance.

Can call → API Compliance Agent (when regulation section is API-specific)
Can call → Codebase Agent (when regulation section requires code-level verification)

call_depth starts at 0.

Codebase Agent

1
Call Depth Limit = 2
Compliance Agent (depth=0) → calls API Agent (depth=1) → calls Codebase Agent (depth=2) → Codebase Agent cannot call further. call_depth is part of LangGraph state and passed in every Inter-Agent Call Tool invocation. If call_depth ≥ 2, the tool returns immediately with a depth-limit message.
2
Agent Decides: Full Pipeline vs Quick Answer
When called by a peer, the receiving agent evaluates the query: broad/complex query → runs its full LangGraph diagnosis loop and returns a complete AgentResult. Narrow/specific query → runs a single Vector Search + LLM call and returns a focused answer. This decision is made by the receiving agent's Relevance Reasoner node based on query scope signals.
3
Results Are Merged Into Caller's State
The calling agent receives AgentResult { findings: List[GapFinding], agent_domain, call_depth } and merges findings into its own state.findings. The final compiled report attributes each finding to its originating agent — "This gap was identified by the API Compliance Agent."
4
Audit Log Tracks Delegation Chain
Every Inter-Agent Call is logged: { caller_agent, called_agent, query, call_depth, result_summary, latency_ms }. The full delegation chain is reconstructable from the audit log — critical for compliance audits where the bank asks "how did the system reach this conclusion?"

Example delegation chain: Compliance Agent is analyzing RBI IT Framework Section 4.3 ("Banks must ensure API endpoints used for data sharing implement strong authentication controls"). Relevance Reasoner routes this to DELEGATE → Inter-Agent Call Tool invokes API Compliance Agent with call_depth=1 and query: "Does the bank's API spec implement strong authentication controls for data sharing endpoints per RBI IT Framework 4.3?" → API Agent runs full pipeline on its namespace → finds 3 endpoints without OAuth2 → returns AgentResult → Compliance Agent merges findings → report attributes gap to API Agent with delegation chain documented.

Service Design
5 Services — What Runs, What It Does
5 Render deployments. Codebase Agent is a separate service from V1 day one — it has unique ingestion needs (code repos, not just PDFs). Report rendering and audit logging inlined into each agent service.
SVC 01
API Gateway Service
FastAPI · Supabase Auth · Rate limiting
Render · Supabase Auth

Single responsibility: Entry point. Validates JWT, routes to correct agent service, creates job records, enqueues ARQ tasks, injects call_depth=0 into LangGraph state. Zero business logic.

  • Job creation: POST /jobs with agent_type + mode → Supabase job record → ARQ task enqueued for agent worker → returns job_id.
  • Mode routing: Modes A + B → ARQ async workers. Mode C → synchronous chat endpoint on the agent service directly (no ARQ).
  • call_depth injection: All ARQ tasks are enqueued with call_depth=0 in LangGraph initial state. Inter-agent calls increment this in the tool — Gateway never sees call_depth > 0.
  • Status polling: GET /jobs/{job_id}/status → reads Supabase job table. Frontend polls every 3s.
SVC 02
Document Ingestion Service
FastAPI · LangChain loaders · text-embedding-004 · pgvector · prance · tree-sitter
Render · Supabase · Cloudflare R2

Single responsibility: Accept any document or code file, parse it, chunk it appropriately, embed it, and store in pgvector under the correct namespace. Handles PDFs, OpenAPI specs, and source code repos.

  • PDF ingestion: LangChain PDFLoader → RecursiveCharacterTextSplitter (chunk_size=800, overlap=100) → batch embed → pgvector INSERT with (agent_domain, doc_type, document_id, chunk_index, version, is_active).
  • OpenAPI spec ingestion: prance resolves $ref chains → each endpoint flattened to a description chunk with endpoint_path metadata → embedded → stored.
  • Code repo ingestion (Codebase Agent): Bank uploads zip of source code → tree-sitter parses each file by language → extracts function/class level chunks with file path + line range metadata → embedded → stored in codebase_bank_doc namespace. This is the RepoGPT pattern applied to compliance.
  • Versioning: Re-ingest marks existing chunks is_active=false, increments version, inserts new chunks as active. Atomic transaction.
  • Raw file storage: All originals → Cloudflare R2 at r2://bankguard/{agent_domain}/{doc_type}/{version}/.
SVC 03
RBI Compliance Agent Service
FastAPI · LangGraph StateGraph · Gemini API · all tools · Jinja2 · WeasyPrint
Render · Gemini API · Supabase · Cloudflare R2

Single responsibility: Run the LangGraph ReAct loop for the RBI Compliance domain. Handles all 3 modes. Can delegate to API Agent and Codebase Agent via Inter-Agent Call Tool. Report rendering and audit logging inlined.

  • LangGraph StateGraph: Nodes: Initialize → Relevance Reasoner → Tool Caller → Evidence Quality Check → Gap Analyzer → Append Finding → Compile Report. Edges: conditional based on agent reasoning output.
  • State checkpointing: LangGraph checkpoints persisted to Redis via Upstash. If worker crashes, ARQ retry resumes from last checkpoint — not from scratch.
  • Tool registration: All 7 tools (Vector Search, Expander, Scraper, Validator, Severity Calculator, → API Agent, → Codebase Agent) registered with LangGraph tool node.
  • Mode A worker: ARQ background task, runs full StateGraph loop. Duration: 5–20 minutes for a full RBI circular.
  • Mode B worker: ARQ background task, simplified loop per question. Duration: 2–5 minutes for 10-15 questions.
  • Mode C endpoint: Synchronous FastAPI endpoint. No ARQ. Dual retrieval + Redis session memory + Gemini. Duration: 2–5 seconds per turn.
  • Audit log: Async fire-and-forget write to Supabase after every Gemini call and every tool call.
SVC 04
API Compliance Agent Service
FastAPI · LangGraph StateGraph · Gemini API · prance · all tools · Jinja2 · WeasyPrint
Render · Gemini API · Supabase · Cloudflare R2

Single responsibility: Run the LangGraph ReAct loop for the API Compliance domain. Identical structure to SVC 03. Can be called by Compliance Agent (call_depth=1) and can call Codebase Agent (call_depth=2). Produces endpoint-level gap findings.

  • When called as peer: Receives { query, context, call_depth } from Inter-Agent Call Tool. Relevance Reasoner evaluates query scope → full pipeline or quick answer. Returns AgentResult to caller.
  • OpenAPI-aware analysis: Bank API spec chunks stored with endpoint_path metadata. Gap findings reference specific endpoint paths directly — no LLM re-parsing of spec.
  • Quick answer mode (when called as peer with narrow query): Single Vector Search → Gemini focused analysis → return finding. Skips full iteration loop. Typically 3–8 seconds.
SVC 05
Codebase Agent Service
FastAPI · LangGraph StateGraph · Gemini API · tree-sitter · all tools (no inter-agent) · Jinja2 · WeasyPrint
Render · Gemini API · Supabase · Cloudflare R2

Single responsibility: Run the LangGraph ReAct loop for codebase compliance analysis. Terminal agent — never calls peer agents. Can be called by both Compliance Agent (depth=1 or 2) and API Agent (depth=2). Analyzes bank source code against RBI security and code quality requirements.

  • Code namespace: pgvector namespace codebase_bank_doc contains function/class level chunks with file path, language, and line range metadata. Ingested via tree-sitter in Ingestion Service.
  • Code-specific analysis: Vector Search retrieves relevant code sections → Gemini reasons about compliance: "Does this function implement proper input validation per RBI requirement X?" → Evidence Validator confirms the cited code chunk exists.
  • Terminal enforcement: Inter-Agent Call Tool is not registered in this agent's tool set. Physically cannot delegate. call_depth check also enforced as backup.
  • RepoGPT pattern: Same semantic code search as RepoGPT — user (or calling agent) can ask natural language questions about the codebase. The LangGraph wrapper adds compliance reasoning and evidence validation on top.
  • Quick answer mode: When called as peer with narrow query (e.g. "does the payment service encrypt card numbers?") → single code namespace search → Gemini → return finding. 3–8 seconds.
End-to-End
Full Diagnosis With Peer Delegation — Step by Step
Tracing the most complex path: Compliance Agent running Full Diagnosis, encountering an API-related section, delegating to API Agent, which then delegates to Codebase Agent.
1
User Starts Full Diagnosis — RBI Compliance Agent
User selects Compliance Agent + Full Diagnosis mode → POST /jobs → Gateway creates job (call_depth=0 in state) → ARQ task enqueued → worker starts LangGraph StateGraph → Initialize node loads all compliance regulation chunks from pgvector.
2
Agent Iterates — Skips, Investigates, Delegates
Agent processes chunks one by one. Section on "preamble and definitions" → SKIP. Section on "access control requirements" → INVESTIGATE → Vector Search retrieves bank policy chunks → gap found → Evidence Validator → Severity Calculator → appended to findings. Section on "API authentication controls" → DELEGATE → Inter-Agent Call Tool invoked with call_depth=1.
3
API Agent Called as Peer (call_depth=1)
API Compliance Agent receives query: "Do the bank's APIs implement authentication controls per RBI IT Framework section 4.3?" Relevance Reasoner evaluates: broad query → run full pipeline on API namespace. Iterates API regulation chunks. Finds 3 endpoints without OAuth2. Encounters a section on TLS implementation in code → DELEGATE to Codebase Agent with call_depth=2.
4
Codebase Agent Called as Peer (call_depth=2)
Codebase Agent receives query: "Does the bank's payment service enforce TLS 1.2+ in code?" Relevance Reasoner: narrow query → quick answer mode. Searches code namespace → retrieves payment service connection code → Gemini: "TLS version is hardcoded as TLSv1.0 in payment_client.py line 47 — violates RBI requirement for TLS 1.2+." → Evidence Validator confirms chunk exists → returns AgentResult to API Agent. Cannot delegate further — call_depth=2.
5
Results Bubble Up — API Agent → Compliance Agent
API Agent merges Codebase Agent's TLS finding into its own findings. Compiles its AgentResult (4 total findings: 3 OAuth2 gaps + 1 TLS code gap) → returns to Compliance Agent. Compliance Agent merges all 4 findings into state.findings. Continues iterating remaining compliance regulation chunks.
6
Compile Final Report
All chunks processed. state.findings deduplicated by regulation clause reference. Each finding tagged with originating agent. Sorted by severity. Jinja2 renders report attributing: "Gap identified by RBI Compliance Agent", "Gap identified by API Compliance Agent via delegation", "Gap identified by Codebase Agent via delegation chain." WeasyPrint → PDF → Cloudflare R2 → pre-signed URL. Job status → READY.
7
Frontend + Follow-up Chat
Frontend polling detects READY → renders gap report with delegation chain visible ("This finding was discovered via API Agent → Codebase Agent"). User can then switch to Free Chat mode to ask follow-up questions about specific findings — e.g. "What exactly needs to change in payment_client.py to fix the TLS gap?" Chat retrieves the relevant code chunk + regulation chunk and answers with evidence.

Agent Framework
LangGraph
V1
langgraph · StateGraph · tool nodes · conditional edges

The Architecture in One Paragraph — For Your ServiceNow Interview
BankGuard V1 is a LangGraph-powered multi-agent compliance platform with three domain agents — RBI Compliance, API Compliance, and Codebase — each running a ReAct StateGraph that reasons section by section through RBI regulation chunks. For each regulation section, the agent decides: skip (irrelevant), investigate (calls Vector Search, Section Expander, RBI Scraper tools), or delegate (calls a peer agent via the Inter-Agent Call Tool). Agents communicate peer-to-peer with no master orchestrator, with a call depth limit of 2 to prevent circular loops. The called agent decides whether to run its full pipeline or return a quick focused answer based on query scope. All document corpora — regulation PDFs, bank policy docs, OpenAPI specs, and source code repos — are ingested into Supabase pgvector dual namespaces per agent domain, with is_active versioning for document updates. The Evidence Validator tool verifies every citation before it enters the report; the Severity Calculator is deterministic — no LLM inconsistency in scoring. LangGraph state is checkpointed to Upstash Redis for crash recovery. Three modes: Full Diagnosis (complete section-by-section ReAct loop), Predefined Questions (Supabase-stored, admin-editable), and Free Chat (dual-namespace retrieval with session memory). Reports rendered via Jinja2 + WeasyPrint to PDF, stored in Cloudflare R2. Total infrastructure cost: $0/month on free tiers. Adding a V2 agent means one new pgvector namespace, one new LangGraph service, and registering in the gateway — zero changes to existing agents.
